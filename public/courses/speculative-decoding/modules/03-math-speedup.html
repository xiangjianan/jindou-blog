快，但一个字都不改

推测解码最惊人的地方：加速是「无损」的，而且能证明。

凭什么说「无损」？

直觉上，掺了小模型的草稿，结果应该会变差吧？但推测解码用了一套叫拒绝采样的统计学技巧，严格证明了：最终输出的每个 token，分布与 target 模型单独生成时一模一样。

换个说法：把推测解码的输出和 target 模型直接生成的输出放在一起，你无法从统计上区分它们。

💡
通用洞察：验证比生成便宜

「先大胆猜测，再一次性验证」是计算机科学的经典套路——缓存预取、CPU 分支预测、数据库查询优化都在用它。大胆猜很便宜，严格验证可以并行，猜对了就白赚。

公式的正确打开方式

别怕，这组公式其实只讲了三句话：

公式 

# 接受 draft 猜的 token x 的概率
P_accept(x) = min(1, p(x) / q(x))

# 被拒绝时，从「残差」重抽
p'(x) = norm(max(0, p(x) - q(x)))

# 最终输出的概率（两者相加）
P(x) = q(x)·min(1, p(x)/q(x))
       + P_reject · p'(x)  =  p(x)
大白话

p 是 target（终审者）的意见，q 是 draft（起草者）的意见……

draft 猜得和 target 一样好甚至更好 → 必过；猜得差 → 按「含金量」打折通过……

没通过的话，从「target 想要但 draft 没猜到」的缺口里补一个……

「draft 猜对被收下的」+「拒绝后补上的」，加起来严格等于 target 自己写的概率——这就是无损证明的核心（Leviathan 2023 / Chen 2023）。

加速多少？一个字母 α 说了算

设单 token 平均接受率为 α，每轮起草 γ 个 token，那么每轮期望收获的 token 数：

公式 

E[accepted] = (1 - α^(γ+1)) / (1 - α)

# 实际加速比（c 为 draft+验证的相对开销）
Speedup ≈ (1 - α^(γ+1)) / ((1 - α) · c)
大白话

每轮平均能「白拿」几个 token——α 越高、γ 越大，收获得越多……

减去跑 draft 模型自己的开销，就是净加速。典型配置（α=0.8、γ=4）实际加速约 2~3 倍。
