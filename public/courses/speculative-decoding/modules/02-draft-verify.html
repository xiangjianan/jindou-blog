起草与验证

小模型猜，大模型判——推测解码的双人舞。

两位角色登场

✏️
Draft 模型（起草者）

小而快，比如只有 1B 参数。写得不完美，但一个 token 成本只有大模型的几十分之一，能一眨眼连写一串草稿。

🏛️
Target 模型（终审者）

大而强，比如 70B 参数。质量完美，但写得慢。它的关键特长是：审稿可以批量做——一次前向传播，同时验证一整串草稿。

💡
关键洞察

大模型的算力就像一辆大巴：载 1 个人和载 5 个人，油耗差不多。既然生成注定一次只能「开一趟」，不如让小模型先塞满一车候选，让大巴一次验完。

裁决规则，用代码说清楚

伪代码 

for draft_token in draft_tokens:
  r = random()  # 0 到 1 的随机数
  if r < min(1,
        p_target[draft_token] / p_draft[draft_token]):
    keep(draft_token)      # 接受
  else:
    resample_from(
      max(0, p_target - p_draft)
    )                       # 拒绝后重采样
    break                  # 后面草稿全部作废
大白话

逐个检查 draft 猜的每个 token……

掷一次骰子来决定是否接受这个 token……

如果 target 也觉得这个 token 不错（两个模型给它的概率越接近，越容易通过），就留下它……

骰子没过？那就不要了……

按「target 想要但 draft 没猜到」的修正分布，重新抽一个替代 token……

第一个被拒的位置之后，剩余草稿全部丢弃——它们的判断已经不可信了。
