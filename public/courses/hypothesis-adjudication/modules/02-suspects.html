两名嫌疑人

两个假说都能解释现有证据。要定罪，得看它们对未来案件的预测是否不同。

为什么需要嫌疑人名单？

「404 能唤醒模型」这个事实有不止一种解释。如果我们随便挑一个喜欢的解释就下结论，那不是科学，是占卜。假说的价值在于：它敢预测还没发生的事。

⚖️
破案思路

两名嫌疑人都声称「我知道 404 为什么有效」。审讯方法：设计几个新案件，让两人各自预测结局——如果预测不同，谁的预测对了，谁就是真凶。

嫌疑人 A：训练分布假说

🧠

「我只认见过千遍的套路」

模型在训练时读过的海量文本里，HTTP 4xx / 5xx 状态码 + 错误文案是高频共现的固定组合。它学到的不是「失败」这个概念，而是一条浅层反射：「非 2xx 开头 = 该报警了」。至于响应体里写什么？它根本不看。

破绽预测：如果失败信号不走状态码、而是写在响应体里（哪怕写得很清楚），它照样装瞎。

嫌疑人 B：语义假说

📖

「我读得懂内容」

模型真的在理解响应的含义。404 有效，不是因为它是 404，而是因为它的错误文案让模型明白了「出事了」。状态码只是恰好常和错误文案一起出现而已。

破绽预测：只要失败信号的内容够明确——哪怕藏在响应体里、用非标准格式——模型也应该能识别失败。

关键分歧点

两人对已有证据的说法完全一致，但在一个新案件上会分道扬镳：

新案件：响应体里写明失败 
// HTTP 状态码：200（一切正常的样子）
{
  "ok": false,
  "reason": "no orders matched",
  "orders": []
}
两名嫌疑人的预测

语义假说：「ok: false + 明确的失败原因？模型当然看得懂，会老实报错。」

训练分布假说：「状态码是 200？我训练时从没被『ok: false』烫过。装瞎，照旧。」

同一个响应，两种结局——这就是我们的裁判局。

谁预测错了，谁就出局。
