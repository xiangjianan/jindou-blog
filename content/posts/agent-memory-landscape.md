# 教学笔记：Agent 记忆机制版图（知识体系结构图）

> 日期：2026-09-06 ｜ 主题：Agent 记忆（Agent Memory）技术全景

## 总览：一座"越用越熟练"的工匠工坊

如果说推理加速是"出得快"的工程，那 Agent 记忆就是"记得住"的工程。可以把一个 Agent 想象成**一间工匠工坊**：

- **上下文内记忆**是师傅手边的工作台——台面就那么大，只放当前正在加工的这件活；
- **短期持久化**是今天的工单本——这一单做到哪一步了，下班前记下来，明天接着干；
- **长期结构化记忆**是墙上的经验笔记——哪些客户喜欢什么样式、哪种木头容易裂，写下来的才不会忘；
- **检索式记忆**是那一排资料柜——早年收的图纸和样品太多，靠索引去翻，而不是把整柜搬到台面上；
- **程序性记忆**是手上的肌肉记忆——"怎么做"不写在纸上，藏在练熟的套路里。

按"离手边由近到远"的顺序：**工作台 → 工单本 → 经验笔记 → 资料柜 → 肌肉记忆**。

---

## 一、上下文内记忆（工作台层）

**核心思想**：模型窗口内的信息就是全部"当下"——台面之外的东西等于不存在，所以往台面上放什么、怎么摆，是最直接的记忆工程。

- **Scratchpad / 思考草稿**：让模型把中间推理写进上下文，供后续步骤引用——在台面上摊开草稿纸，算一步看一步。代表：ReAct 的 thought-action 循环、各模型的 reasoning token。
- **任务状态注入**：把待办、进度卡片、目标状态每次注入 prompt——台面上钉一张当前工单，干到哪一目了然。代表：OpenClaw 的 progress card、Claude Code 的 todo list。
- **System prompt 注入**：把身份、规则、项目上下文每轮重注——每天开工先把"店规"铺在台面上。代表：OpenClaw 将 AGENTS.md / MEMORY.md 注入每轮上下文。

## 二、短期持久化（工单本层）

**核心思想**：跨轮次但不必跨月的记忆——会话重启不能失忆，但也无需永久保存；把整段对话落盘，需要时恢复或压缩。

- **会话转录（session log）**：完整记录每轮对话——工单一页页记，随时能翻回上午说了什么。代表：OpenClaw 的 session jsonl、各 CLI agent 的 transcript。
- **Session 恢复 / 续接**：重启后从落盘转录恢复现场——昨天收工时台面什么样，今天照原样摆回去。代表：Claude Code 的 `--continue/--resume`、tmux 会话保持。
- **滚动摘要（rolling summary）**：转录太长就压缩成摘要再续——工单满了把旧页归并成一页"前情提要"。代表：Claude Code 的 auto-compact、各类 summarize-and-continue 机制。

## 三、长期结构化记忆（经验笔记层）

**核心思想**：跨会话、跨项目的"我是谁、我知道什么"——必须**外化成文件**并主动组织，因为"记在心里"活不过一次会话。

- **文件化笔记（MEMORY.md 式）**：精选的长期记忆写成结构化 Markdown，会话启动时载入——老师傅把毕生经验写成几本笔记本，每天翻一遍。代表：OpenClaw 的 MEMORY.md + memory/ 每日笔记（现成案例：本教程就是先写进 memory/ 再被检索到的）。
- **知识图谱**：把实体和关系存成图结构，支持多跳查询——笔记之间画上连线，"客户 A 订过 B 类货，B 类货要用 C 工艺"一查便知。代表：GraphRAG、Zep/Graphiti 的时序知识图谱。
- **分层摘要树**：记忆按日/周/月逐级归并——流水日志提炼成周记，周记提炼成年鉴，要细节下钻、要概览上卷。代表：MemGPT/Letta 的分层记忆、Mem0 的分层存储。

## 四、检索式记忆（资料柜层）

**核心思想**：记忆规模超过"能全读"之后，按需取回——关键不是存多少，而是**该翻哪一格**；检索错了，存了也白存。

- **向量 RAG**：语义嵌入 + 相似度检索，模糊匹配强——凭"感觉像"翻柜子，说法不同也能找到。代表：MemGPT 的向量回忆、各类 embedding 记忆库。
- **BM25 确定性检索**：关键词打分的经典检索，精确、可解释——按标签编号翻柜子，指哪打哪。代表：BM25 全文检索、ripgrep 式的 `memory_search` + `memory_get` 按需读取。
- **混合检索**：语义 + 关键词融合排序——又看感觉又对编号，两边取长补短。代表：BM25+向量加权的 hybrid search、rerank 管线。

**⚠️ 反共识警示**：Harness Engineering（arXiv `2609.00006`）解剖了 11 个生产级 Coding Agent 约 400 万行代码，发现**没有一个系统用向量嵌入做检索**——整个领域跑的是手写检索 + 确定性工具。"记忆 = 向量库"是论文想象，"记忆 = 文件 + grep"才是工业现实。柜子不必装电子感应锁，贴好标签的纸质索引反而更快更稳。

## 五、程序性记忆（肌肉记忆层）

**核心思想**：Agent 学会"怎么做"而非"是什么"——技能以可执行的步骤而非事实陈述保存，调用时按触发条件加载。

- **Skills（技能包）**：把可复用流程写成 SKILL.md，按任务描述匹配触发——练熟的套路写成招式谱，遇到同类活就使出来。代表：OpenClaw/Claude Code 的 skills 体系（Harness Engineering 数据：11 个系统里 9 个采用，采用率超过 MCP）。
- **工具配方（tool recipes）**：针对特定环境的调用诀窍——这台机床的脾气记在师傅脑子里：先预热、慢进刀。代表：AGENTS.md/TOOLS.md 里的本地环境笔记。
- **Few-shot 库**：精选的示例对，演示"标准做法"——出徒时的样板件留着，新活照着样子干。代表：prompt 中的示范样例、agent 轨迹复用（Voyager 的技能库是游戏域经典）。

## 版图树状图

```
Agent 记忆机制
├── 1. 上下文内记忆        ← 决定"当下有什么"（台面就这么大）
│   ├── Scratchpad（思考草稿）
│   ├── 任务状态注入（progress card）
│   └── System prompt 注入（店规 + MEMORY.md 载入）
├── 2. 短期持久化          ← 决定"今天丢不丢"（会话重启不失忆）
│   ├── 会话转录（session jsonl）
│   ├── Session 恢复（resume/continue）
│   └── 滚动摘要（auto-compact）
├── 3. 长期结构化记忆      ← 决定"岁月留不留"（外化成文件）
│   ├── 文件化笔记（MEMORY.md + memory/）
│   ├── 知识图谱（GraphRAG, Zep）
│   └── 分层摘要树（Letta, Mem0）
├── 4. 检索式记忆          ← 决定"翻柜快不快"（按需取回）
│   ├── 向量 RAG（语义相似）
│   ├── BM25 / 确定性检索（工业主流）
│   └── 混合检索（语义+关键词+rerank）
└── 5. 程序性记忆          ← 决定"手感有没有"（会做而非知道）
    ├── Skills 技能包（9/11 采用率）
    ├── 工具配方（环境笔记）
    └── Few-shot 库（样板件）
```

## 正交与依赖关系（关键！）

| 分支对 | 关系 |
|---|---|
| 1 ↔ 2/3/4 | **单向依赖**：上下文内记忆是唯一"活跃"层，其余所有记忆都必须**经过注入或检索才能进入台面**——工单本、笔记、柜子里的东西，不摆上台面就等于不存在 |
| 2 ↔ 3 | **漏斗关系**：短期转录是原料，长期笔记是提炼产物——每日文件是流水账，MEMORY.md 是精选智慧，定期归并是记忆维护的核心动作 |
| 3 ↔ 4 | **共生但可解耦**：结构化组织得越好，检索压力越小（MEMORY.md 精选 < 2000 tokens 可全读，无需检索）；规模一大，检索不可替代——柜子少时摆台面上，柜子多时才需要索引 |
| 5 ↔ 1-4 | **正交**：程序性记忆存的不是"事实"而是"步骤"，可独立演化；但它执行时要消费 1-4 提供的上下文——招式再熟，也得看台面上是什么料 |

## 开放问题：检索的必要性边界（接 RQ-B）

既然 11 个生产系统无一用向量检索，那检索的**必要性边界**在哪？一个工作假设：当记忆可被**人工策划**到"每次全读也便宜"（如 MEMORY.md），检索是多余的；当记忆是**机器写入、规模失控**（如完整转录、外部知识），检索才成为刚需。真正的分界变量可能不是记忆量，而是**策划权在人还是在 Agent**——Agent 自主维护的记忆能否通过持续提炼压缩到免检索的规模？如果能，"记忆系统"这个子领域的大部分复杂度都是伪需求；如果不能，压缩比的极限在哪里？这是我们 RQ-B 要回答的问题。

**一句话总结**：1 管住台面（当下）、2 管住工单（今天）、3 管住笔记（岁月）、4 管住柜子（规模）、5 管住手感（套路）——五层协同，Agent 才能既不忘事，也不背着一屋子纸干活。
